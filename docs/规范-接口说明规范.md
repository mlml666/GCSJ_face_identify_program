# 接口说明规范（一期）

前后端、测试三方对齐接口的唯一依据。**先定接口，再写代码**：接口定完前后端各自用 Mock 并行开发。

## 一、总则

- 统一前缀 `/api/v1`
- 请求与响应均为 JSON，UTF-8 编码
- 时间格式 `yyyy-MM-dd HH:mm:ss`，日期 `yyyy-MM-dd`
- 一期鉴权用 session cookie，前端 `fetch` 需带 `credentials: 'same-origin'`
- 每个接口都要做角色校验（管理员 / 任课教师 / 教务只读）

## 二、URL 与命名

- 资源用复数名词，层级不超过 3 层：`/api/v1/students`、`/api/v1/courses/{id}/students`
- 用 HTTP 方法表达动作：GET 查、POST 建、PUT 改、DELETE 删
- 少数业务动作用动词后缀：`/verify`（比对）、`/review`（人工复核）、`/import`（批量导入）、`/rebuild`（重建特征）
- 路径全小写，多词用连字符：`/attendance/sessions`

## 三、统一响应格式

成功：

```json
{ "code": 0, "message": "ok", "data": { "student_no": "2024132031" } }
```

失败：

```json
{ "code": 3001, "message": "学生不存在", "data": null }
```

### 状态码与业务码对照

| HTTP | 业务 code | 含义 |
| --- | --- | --- |
| 200 | 0 | 成功 |
| 201 | 0 | 创建成功 |
| 400 | 1001 | 参数校验失败 |
| 400 | 1002 | 文件格式或大小不合规 |
| 401 | 2001 | 未登录 / 会话过期 |
| 403 | 2002 | 无权限（越权访问他人数据） |
| 404 | 3001 | 资源不存在 |
| 409 | 3002 | 冲突（学号重复、考勤已结束） |
| 500 | 5000 | 服务器内部错误 |

约定：`code` 由后端统一定义，前端只判断 `code === 0`；**不要**用 HTTP 200 包住业务错误。

## 四、字段与分页

- 学号：`student_no`（字符串，唯一标识）
- 相似度：`similarity`，float，保留四位小数，范围 0—1
- 是否通过：`passed`，bool
- 时间字段：`create_time` / `update_time`
- 分页：`?page=1&page_size=20`，`data` 返回 `{ "items": [], "total": 42, "page": 1, "page_size": 20 }`

## 五、人脸比对接口的特殊约定（容易错）

**比对未通过不是错误。** 返回 HTTP 200 + `code: 0`，靠 `data.passed` 表达结果：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "passed": false,
    "similarity": 0.3125,
    "threshold": 0.6000,
    "suggestion": "光线或角度不佳，建议重拍；也可人工复核"
  }
}
```

只有系统层失败（照片无法检测到人脸、文件损坏、特征缺失）才返回 `code != 0`。前端禁止把"未通过"渲染成报错弹窗。

## 七、单个接口的写法（模板）

每个接口在实现前先按下面 8 项写进本文件，缺一项不算定稿：

1. **接口名与需求号**
2. **方法与路径**
3. **权限**（哪类角色可调用）
4. **请求参数表**（字段 / 类型 / 必填 / 说明）
5. **请求示例**
6. **成功响应示例**
7. **失败示例与业务码**
8. **备注**（幂等性、并发、边界条件）

### 示例：现场照片比对

**① 接口名**：现场照片 1:1 比对（P0-08）

**② 方法与路径**：`POST /api/v1/attendance/sessions/{session_id}/verify`

**③ 权限**：任课教师（仅本人课程）、管理员

**④ 请求参数**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `student_no` | string | 是 | 当前被点名学生学号 |
| `file` | file | 是 | 现场照片，jpg/png，≤5MB |

**⑤ 请求示例**：`multipart/form-data`，字段同上

**⑥ 成功响应**

```json
{ "code": 0, "message": "ok", "data": { "passed": true, "similarity": 0.8731, "threshold": 0.6, "status": "出勤" } }
```

**⑦ 失败示例**

```json
{ "code": 1002, "message": "仅支持 jpg/png，单张不超过 5MB", "data": null }
```

```json
{ "code": 3001, "message": "照片中未检测到人脸，请重拍", "data": null }
```

**⑧ 备注**：同一学生重复提交以最后一次为准并留痕；比对结果写入考勤记录；阈值变更需记录操作日志。

## 八、版本与变更

- 路径版本 `/api/v1`；破坏性变更才升 `v2`，不要随意加 `v1.1`
- 字段只增不删：新字段可加，删除字段前先闲置一个版本并通知前端
- 任何接口变更必须在 PR 描述里写「接口变更」，并同步本文件与测试
- 联调前先确定字段命名，避免前后端各起一套名字

## 九、校验与安全

- 服务端二次校验：文件大小/格式、学号存在性、课程归属、角色权限
- 越权检查：教师只能访问本人课程数据，学生（二期）只能看本人记录
- **不返回**人脸特征向量到前端，也不在列表接口里返回他人照片路径
- 上传接口超限返回 `1002`；无权限返回 `2002`；资源不存在返回 `3001`
