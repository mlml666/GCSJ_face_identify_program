# 运行规范（一期 Web 端）

## 一、适用范围

一期全部代码：Flask 服务、页面模板、静态资源、数据脚本。所有成员提交前按本规范自检。

## 二、目录约定

```
app.py            唯一启动入口（一期保持单入口，不拆多进程）
config.py         配置与常量（SECRET_KEY、上传限制、比对阈值）
templates/        Jinja2 模板，按页面命名：login.html、index.html、call.html …
static/           css/  js/  img/ 按类型分目录
data/             本地上传照片与 sqlite 库（不进 Git）
scripts/          一次性脚本（特征提取、名单导入），不放路由
docs/             文档与规范
.conda/           项目内虚拟环境（不进 Git）
```

命名规则：文件与变量用小写 + 下划线；模板用「页面名.html」；静态资源**不要用中文名**。

## 三、启动方式

### 3.1 开发模式（日常）

```powershell
.\.conda\python.exe app.py
```

- `debug=True`：改代码自动重载，报错页带堆栈
- 默认地址 `http://127.0.0.1:5000`
- 端口被占用：把 `app.run()` 改成 `app.run(port=5001)`，并在群里说一声

### 3.2 演示 / 预验收模式

```powershell
.\.conda\python.exe -m flask --app app run --host 127.0.0.1 --port 5000
```

关闭自动重载，避免重载子进程同时写 SQLite 造成锁表。

### 3.3 启动自检三条

```powershell
.\.conda\python.exe -c "import sys, flask; print(sys.executable); print(flask.__version__)"
.\.conda\python.exe -m pip check
netstat -ano | findstr :5000
```

第一条的路径必须落在项目 `.conda\` 下，否则说明用错解释器。

## 四、配置规范

所有可变项集中在 `config.py`，禁止散落在路由里：

| 配置项 | 建议值 | 说明 |
| --- | --- | --- |
| `SECRET_KEY` | 从环境变量读，缺省值仅供开发 | 上试运行必须显式设置 |
| `MAX_CONTENT_LENGTH` | 5 \* 1024 \* 1024 | 单张照片上限 5MB |
| `ALLOWED_EXTENSIONS` | jpg / jpeg / png | 服务端二次校验 |
| `FACE_MATCH_THRESHOLD` | 0.6 | 欧氏距离阈值，`distance <= 该值` 判通过；调整须写操作日志 |

分页参数（`page` / `page_size`）目前只出现在接口约定里，一期的接口都还没实现，所以 `config.py` 暂不设分页上限常量；等列表接口落地时再加，避免死配置。

补充要求：

- 路径一律用 `Path(__file__).parent` 拼，不写死 `E:\...`
- 阈值、上传限制改动属于业务变更，需同步接口文档并通知测试
- 禁止把密钥、数据库密码提交到仓库

## 五、编码规范（Python）

1. **模块头**：文件开头 3 行内说明用途，例如 `"""学生信息接口：增删改查 + 批量导入。"""`
2. **函数注释**：每个函数写 docstring，说明输入、输出、异常，一事一句，不要写 `# 循环` 这种无信息注释
3. **风格**：PEP8，4 空格，行宽 100；变量 `snake_case`，常量 `UPPER_CASE`，类 `PascalCase`
4. **分层**：路由函数只做参数校验 + 调 service；业务超过 30 行就拆到 `service.py`
5. **错误处理**：不裸抛异常给前端，统一用响应封装（见接口规范）
6. **模板**：复杂计算在视图里算好再传，模板里少写判断
7. **禁止**：提交 `print` 调试、注释掉的死代码、明文密码、`eval`

## 六、提交前检查清单

- [ ] 用项目解释器跑通：启动 → 登录 → 改动的那个页面
- [ ] `.\.conda\python.exe -m compileall -q app.py` 无语法错误
- [ ] `git status` 里没有 `.db`、照片、`.conda/`、`.conda-pkgs/`
- [ ] 改了接口的，已同步 `docs/规范-接口说明规范.md`
- [ ] 更新 `docs/PROGRESS.md` 和 `docs/progress/<自己>.md`
- [ ] 提交信息符合 `feat: / fix: / docs: / chore:` 格式

## 七、日志规范

- 开发调试用 `app.logger.info/debug`，不留在提交代码里刷屏
- 关键业务必须落库（`operation_log` 表）：发起考勤、比对结果、人工复核、阈值调整、数据导出、特征删除
- 日志**不得**记录密码、完整人脸特征向量、身份证等敏感信息

## 八、数据与文件规范

- 上传照片命名：`学号+姓名.jpg`，存放 `data/photos/`
- 服务端校验：扩展名白名单 + 大小 ≤5MB + 能否提取人脸，三者都过才算成功
- 数据库：`data/facs.db`；改表结构必须写 `scripts/migrate_xxx.py`，不手改线上库
- 照片与人脸特征只在本机保存，禁止上传网盘、聊天群、GitHub

## 九、红线

- 不提交 `.conda/`、`data/`、`*.db`
- 不直接往 `main` 提交；功能走 `feature/*` → PR → `develop`
- demo 里的明文账号不得搬进正式代码（正式版必须密码哈希）
- 演示分支与正式代码不混用同一个文件
